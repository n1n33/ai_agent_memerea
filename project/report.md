## 2. Постановка задачи и контекст

Проект относится к области интеллектуального поиска и генерации ответов на основе документов. Основная задача — не просто сгенерировать ответ языковой моделью, а сначала найти релевантные фрагменты в учебных материалах и использовать их как контекст для ответа

Потенциальный пользователь системы — студент, преподаватель или учащийся, которому нужно быстро получить объяснение по теме из загруженных учебных материалов. Пользователь открывает веб-интерфейс, задаёт вопрос по математике и получает ответ на русском языке с указанием использованных источников

В терминах ИИ задача формулируется как Retrieval-Augmented Generation:

- **входные данные:** текстовые учебные документы и вопрос пользователя;
- **выход системы:** сгенерированный ответ на русском языке;
- **промежуточный результат:** найденные релевантные фрагменты документов;
- **ограничения:** локальная работа без передачи данных во внешние API, приемлемое время ответа, опора на документы, возможность обновления базы знаний.

Для оценки качества используются:

- средняя оценка качества ответа по тестовым сценариям;
- среднее время отклика;
- количество успешно обработанных запросов;
- наличие релевантного контекста в ответе.

Такие метрики выбраны, потому что для RAG-системы важны не только формальная правильность ответа, но и скорость, устойчивость работы и способность находить подходящие материалы в базе знаний.

В проекте используются открытые учебные материалы по математике. Они применяются не для обучения языковой модели, а для построения локальной базы знаний.

Исходные данные расположены в директории:

- `Geometry.md`;
- `Intermediate_Algebra.md`;

- `Prealgebra.md`;

Тип данных — текстовые учебные материалы. Основная предобработка включает загрузку документов, разбиение текста на фрагменты, вычисление эмбеддингов и сохранение векторного индекса FAISS.

После обработки создаётся индекс:


## 4. Модели и подходы

В проекте не выполняется обучение модели с нуля. Используется подход RAG, который объединяет семантический поиск по документам и генерацию ответа языковой моделью.

В качестве базового подхода можно рассматривать прямое использование LLM без поиска по документам. Такой подход проще, но хуже подходит для задачи, потому что модель может отвечать без опоры на конкретные учебные материалы и потенциально генерировать недостоверную информацию.

Финальный подход включает:

- загрузку документов из локальной папки;
- разбиение текста на фрагменты;
- построение эмбеддингов с помощью `intfloat/multilingual-e5-base`;
- сохранение векторного индекса FAISS;
- поиск top-k релевантных фрагментов;
- генерацию ответа локальной моделью `edu-qwen-14b`.

В качестве LLM используется модель Qwen 2.5 14B, запускаемая локально через Ollama. Конфигурация модели хранится в `Modelfile`, а параметры системы — в `config.yaml`.

Ключевые параметры:

```yaml
embedding_model: "intfloat/multilingual-e5-base"
embedding_device: "cuda"
chunk_size: 800
chunk_overlap: 150
search_k: 5
llm_model: "edu-qwen-14b"
```

## 5. Экспериментальный протокол и результаты

Для проверки системы используется набор тестовых вопросов из файла:

```text
test_dataset_expanded.json
```

Скрипт `evaluate.py` последовательно отправляет вопросы в RAG-систему, фиксирует ответы, время обработки и оценку качества. По результатам формируются отчёты:

```text
VALIDATION_REPORT.md
FULL_TEST_LOGS.md
evaluation_results.csv
MODEL_REPORT.md
FINAL_REPORT.md
```

Сравнение подходов:

| Модель / конфигурация | Описание | Оценка качества | Время ответа | Комментарий |
|---|---|---:|---:|---|
| LLM без RAG | Ответ только на основе знаний модели | не использовалась как финальная | зависит от модели | Нет привязки к документам |
| EduRAG + Qwen 14B | Поиск FAISS + генерация через Qwen | до 5.00 / 5.00 по отчёту валидации | около 17.87 сек. в отчёте | Финальная конфигурация |
| Ранний тест модели | Проверка на меньшем наборе сценариев | 4.36 / 5.00 | около 31 сек. | Использовалась для первичной оценки |

Финальной выбрана конфигурация EduRAG с локальной моделью Qwen 14B, так как она обеспечивает баланс между качеством ответов, локальностью работы и возможностью объяснять ответы через найденные источники.

## 7. Наблюдаемость, конфигурация и безопасность

Архитектура решения состоит из нескольких этапов:

```text
Учебные документы
        ↓
Загрузка документов
        ↓
Разбиение на фрагменты
        ↓
Построение эмбеддингов
        ↓
FAISS-индекс
        ↓
Вопрос пользователя
        ↓
Поиск релевантного контекста
        ↓
LLM Qwen через Ollama
        ↓
Ответ в Streamlit-интерфейсе
```

Основные компоненты проекта:

- `app.py` — веб-интерфейс Streamlit;
- `src/document_loader.py` — загрузка документов;
- `src/vector_store.py` — создание и загрузка FAISS-индекса;
- `src/rag_chain.py` — RAG-цепочка;
- `src/config.py` — загрузка конфигурации;
- `evaluate.py` — тестирование качества системы.

В проекте не реализован REST API с endpoints `/health` и `/predict`. Вместо этого используется веб-интерфейс Streamlit, доступный после запуска по адресу:

```text
http://localhost:8501
```

Запуск:

```bash
streamlit run app.py
```

Технологический стек:

- Python;
- Streamlit;
- LangChain;
- FAISS;
- HuggingFace Embeddings;
- Ollama;
- Qwen 2.5;
- PyTorch;
- Loguru.

## 8. Ограничения и дальнейшая работа

Текущая версия проекта является рабочим прототипом и имеет ряд ограничений:

- нет отдельного REST API;
- нет авторизации пользователей;
- история диалога хранится только в рамках текущей Streamlit-сессии;
- отсутствует полноценная директория `tests/` с модульными тестами;
- качество ответов зависит от полноты документов в базе знаний;
- для комфортной работы желательно наличие GPU NVIDIA с CUDA;
- при добавлении новых документов требуется пересборка FAISS-индекса;
- система работает только с локальными заранее подготовленными материалами.

В дальнейшем можно добавить:

- REST API на FastAPI;
- endpoints `/health` и `/predict`;
- Docker-конфигурацию;
- автоматическое обновление индекса при изменении документов;
- поддержку нескольких коллекций документов;
- хранение истории запросов;
- авторизацию пользователей;
- полноценные unit- и integration-тесты;
- расширение набора учебных материалов;
- более строгую оценку качества RAG-ответов.
