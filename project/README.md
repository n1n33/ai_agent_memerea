## 2. Структура проекта

Проект организован в следующей структуре:

- `configs/` - основные параметры конфигурации системы:
  - `config.yaml` – конфигурационный файл проекта: пути к данным, параметры эмбеддингов, LLM и поиска;
  - `Modelfile` – файл конфигурации локальной модели Qwen для запуска через Ollama.
- `artifacts/` - артифакты работы системы, логи и прочее:
  - `evaluate.py` - скрипт для тестирования качества работы системы;
  - `test_dataset_expanded.json` - тестовый набор вопросов для проверки системы;
  - `evaluation_results.csv` - результаты экспериментов и оценки качества;
  - `FINAL_REPORT.md` – итоговый отчёт;
  - `MODEL_REPORT.md` – отчёт по тестированию модели;
  - `VALIDATION_REPORT.md` - протокол валидации системы;
  - `FULL_TEST_LOGS.md` - подробные логи тестовых запусков.
- `src/` – основной код проекта:
  - `data/` - загрузка и подготовка данных;
    - `data/download_data.py` - скрипт для загрузки или подготовки данных;
    - `document_loader.py` - загрузка и обработка документов;
  - `models/` - применение модели;
    - `rag_chain.py` - построение RAG-цепочки: поиск релевантных фрагментов и генерация ответа;
  - `service/` - запуск сервиса;
    - `api.py` - API;
    - `app.py` - UI через Streamlit;
    - `config.py` - загрузка конфигурации;
    - `start.ps1` - команда централизованного запуска всех сервисов;
    - `start_services.py` - алгоритм централизованного запуска сервисов;
    - `stop.ps1` - команда централизованной остановки всех сервисов;
    - `stop_services.py` - алгоритм централизованной остановки сервисов;
    - `vector_store.py`создание и загрузка векторной базы FAISS;
  - `models/rag_chain.py` - построение RAG-цепочки: поиск релевантных фрагментов и генерация ответа;
  - `utils/visualization.py` - формирование отчётов по результатам тестирования.
- `data/` – данные проекта:
  - `raw/math_dataset/` - исходные учебные материалы по математике;
  - `processed/faiss_index/` - сохранённый FAISS-индекс для семантического поиска.
- `requirements.txt` – зависимости проекта, необходимые для запуска RAG-системы.
- `README.md` – основная документация по установке, настройке и запуску проекта.

## 3. Требования и установка

### 3.1. Требования

Для запуска проекта необходимы:

- Python `>= 3.10`;
- `pip` для установки зависимостей;
- установленный **Ollama** для локального запуска языковой модели;
- локальная модель `edu-qwen-14b`, созданная на основе `qwen2.5:14b-instruct-q3_K_M`;
- рекомендуется GPU NVIDIA с поддержкой CUDA для ускорения работы эмбеддингов и LLM;
- при отсутствии CUDA часть вычислений может выполняться на CPU, но скорость работы будет ниже.

Основные используемые технологии:

- Streamlit;
- FastAPI;
- LangChain;
- FAISS;
- HuggingFace Embeddings;
- Ollama;
- Qwen 2.5 14B.

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd ai_project

# Создать виртуальное окружение
python -m venv .venv
```

Активация окружения:

```bash
# Windows
.venv\Scripts\activate
```

```bash
# Linux / macOS
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Дополнительно необходимо установить Ollama и загрузить базовую языковую модель:

```bash
ollama pull qwen2.5:14b-instruct-q3_K_M
```

После этого нужно создать пользовательскую модель проекта из файла `Modelfile`:

```bash
ollama create edu-qwen-14b -f Modelfile
```

Приложение можно запустить одной командой. Скрипт поднимает Ollama, FastAPI и Streamlit:

```bash
.\scripts\start.ps1
```

Остановить все сервисы:

```bash
.\scripts\stop.ps1
```

Остановить только API и Streamlit, оставив Ollama запущенной:

```bash
.\scripts\stop.ps1 --keep-ollama
```

Логи сервисов сохраняются в `artifacts/logs/`. Если нужно запустить компоненты вручную:

```bash
ollama serve
uvicorn src.service.api:app --reload
py -m streamlit run src/service/app.py
```

После запуска интерфейс будет доступен в браузере по адресу:

```text
http://localhost:8501
```

## 4. Как запустить проект

Перейти в папку проекта и активировать окружение:

```bash
ollama pull qwen2.5:14b-instruct-q3_K_M
```

Проект запускается одной командой:

```bash

```

Остановка:

```bash

```

После запуска веб-интерфейс будет доступен в браузере по адресу:


4. Получить ответ, сгенерированный на основе найденных фрагментов из базы знаний.

## 5. Данные

В проекте используются открытые учебные материалы по математике, представленные в формате Markdown. Данные применяются не для обучения языковой модели, а для формирования локальной базы знаний, по которой выполняется семантический поиск в RAG-системе.

Исходные файлы расположены в директории:

```text
data/raw/math_dataset/
```

В набор входят материалы по следующим разделам:

- `Counting_Probability.md`;
- `Geometry.md`;
- `Intermediate_Algebra.md`;
- `Number_Theory.md`;
- `Prealgebra.md`;
- `Precalculus.md`.

После обработки документов система разбивает тексты на фрагменты, строит эмбеддинги и сохраняет векторный индекс FAISS в директории:

```text
data/processed/faiss_index/
```

В репозитории также находится тестовый набор вопросов:

```text
artifacts/test_dataset_expanded.json
```

Он используется для проверки качества ответов системы при запуске:

```bash
artifacts/python evaluate.py
```

Результаты тестирования сохраняются в файлах:

```text
artifacts/VALIDATION_REPORT.md
artifacts/FULL_TEST_LOGS.md
artifacts/evaluation_results.csv
```

Большие конфиденциальные данные в проекте не используются. При необходимости исходные учебные материалы можно обновить или заменить, добавив новые документы в папку:

```text
data/raw/math_dataset/
```

После добавления новых данных нужно заново пересобрать базу знаний через веб-интерфейс кнопкой **«Пересобрать базу знаний»** или программно через модули загрузки документов и векторного хранилища.

## 6. Тесты

Отдельной директории `tests/` с модульными тестами в проекте нет. Проверка работоспособности реализована в виде sanity-check / evaluation-сценария через скрипт `evaluate.py`.

- сохраняет оценки качества, время ответа и подробные логи.

```bash
cd ai_project
```

```bash
# Windows
.venv\Scripts\activate
```

```bash
# Linux / macOS
source .venv/bin/activate
```

```bash
python artifacts/evaluate.py
```

Перед запуском проверки необходимо убедиться, что:

- установлены зависимости из `requirements.txt`;
- запущен сервис Ollama;
- создана модель `edu-qwen-14b`;
- существует локальный FAISS-индекс в `data/processed/faiss_index/`.

После выполнения скрипта формируются или обновляются файлы:

```text

artifacts/FULL_TEST_LOGS.md
```

Также в проекте уже присутствуют сохранённые результаты предыдущих запусков:

## 8. Ограничения и дальнейшая работа

В текущей версии проект является рабочим прототипом локальной RAG-системы, но имеет ряд ограничений. Система ориентирована на работу с заранее подготовленными учебными материалами и не выполняет дообучение языковой модели. Качество ответов зависит от полноты документов в `data/raw/math_dataset/`, качества найденных фрагментов и возможностей локальной модели `edu-qwen-14b`.

Основные ограничения:

- нет отдельного REST API, взаимодействие реализовано только через Streamlit-интерфейс;
- отсутствует авторизация пользователей и разграничение доступа;
- история диалога хранится только в рамках текущей Streamlit-сессии;
- нет полноценного набора модульных тестов в директории `tests/`;
- оценка качества реализована через отдельный evaluation-скрипт, а не через автоматический CI-пайплайн;
- для комфортной работы желательно наличие GPU NVIDIA с CUDA;
- при добавлении новых документов требуется пересборка FAISS-индекса;
- система работает только с локально подготовленной базой знаний и не подключается к внешним источникам данных.

В дальнейшем проект можно развивать в следующих направлениях:

- добавить REST API, например на FastAPI, для интеграции с другими сервисами;
- реализовать полноценные модульные и интеграционные тесты;
- добавить хранение истории запросов и ответов пользователей;
- реализовать авторизацию и роли пользователей;
- добавить поддержку нескольких коллекций документов;
- улучшить оценку качества ответов с помощью более формальных метрик;
- добавить автоматическое обновление индекса при изменении документов;
- реализовать выбор модели и параметров поиска через интерфейс;
- добавить Docker-конфигурацию для более удобного развёртывания;
- расширить набор учебных материалов и поддерживаемых предметных областей.
